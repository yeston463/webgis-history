# GIS 方法学说明（GIS Methods）

本文件说明《山海新篇》**建成区时空对比**所采用的**空间分析方法、算法依据与精度处理**。核心原则：**面积一律采用测地计算，严禁经纬度平方近似；重叠区域不重复计入。**

---

## 0. 统一约定

- **坐标与投影**：前端地图为 Web Mercator（EPSG:3857）显示；面积计算使用 Turf.js 的**球面几何**（`turf.area` 基于球体模型，单位为平方米），不依赖显示投影的平面量算。
- **底图**：统一使用天地图在线矢量瓦片（`vec_w` + `cva_w`，合规国界/南海诸岛/九段线，审图号 GS(2023)336号），缩放硬锁至 Z17；底图仅作参照，**不进入任何面积/高度计算**。网络不可用时专题矢量层与 3D 建筑轮廓仍正常渲染，仅底图瓦片缺失。
- **空间运算库**：Turf.js 6.5.0（本地 vendor）。

---

## 1. 功能A · 城市建成区卷帘对比（Spatial Change / Area）

### 1.1 目标
- 统计研究区内建成区面积（起始年 vs 对比年）。
- 计算面积变化量与变化率。
- 显示新增建成区的空间分布（差值面）。

### 1.2 数据与图层
- 数据：`data/urban-expansion/{city}_{year}.geojson`，采用 **Atlas of Urban Expansion（AUE, 2016）**真实建成区轮廓——由 Landsat 影像解译的城市 urban extent，重投影至 WGS84 后为若干多边形斑块（一个 `FeatureCollection`，含多个 `Polygon`）。三个时期约 1990 / 2000 / 2014。
- 渲染：双图卷帘——左图为起始年（橙色），右图为对比年（蓝青色），右图通过 `clip-path` 按卷帘位置裁切，形成左右对比的"拉帘"效果（`map.css` + `analysis.js` 拖拽逻辑）。

### 1.3 面积计算（重点）
- **逐个斑块测地面积求和**本不可取：斑块之间会重叠，直接对 `MultiPolygon` 各子面求和会**重复计入重叠区**。
- **正确做法**：先用 `turf.union` 将同年份的所有斑块合并为单一多边形（`mergeBuiltup()`），再对合并结果调用 `turf.area` 求总面积。
  - 合并后面积 = 真实覆盖面积（去重叠）。
  - 例（深圳 1990→2014，AUE 真实数据）：1990 合并面积 ≈ 145 km²；2014 合并面积 ≈ 1257 km²。
- **变化量**：`Δ = 面积(对比年) − 面积(起始年)`。
- **变化率**：`率 = Δ / 面积(起始年) × 100%`。

### 1.4 新增建成区（差值面）
- 对**合并后的**两个年份几何做布尔差：`turf.difference(合并(对比年), 合并(起始年))`。
- 结果几何即为"对比年有、起始年无"的建成区空间分布，渲染为金色高亮面（`newbu` 图层）。
- 其面积即为"新增建成区面积"，与 `Δ` 在几何意义上一致（重叠处理后）。
- **注意**：Turf v6 的 `difference` 不接受 `FeatureCollection` 直接入参，须传入要素（`features[0]`）；本项目已按此修正并先合并，结果已通过 `turf.area` 实测校验。

### 1.5 趋势图
- 对城市所有可用年份分别合并求面积，得到面积—年份序列，用 ECharts 折线图（面积填充）展示扩张趋势。

## 1A. 功能A+ · 九城建筑三维演化（OSM 真实轮廓 × AUE 建成区年代）

> **版本说明（2026-11-06）**：此前的「GHSL 370m 网格体块（体块版）」已按要求删除，产物与统计数字**作废**并归档于 `_archive/2026-11-06-removed/`（含 1990=6,259 格 / 2015=9,948 格、基底 71.3/255.7 km² 等旧数字）。本节为现行方法。

### 1A.1 目标
- 用**逐栋真实建筑轮廓**（OpenStreetMap）呈现九城的现状三维城市形态；
- 用**真实建成区范围**把这些轮廓切成分层年代，做成可播放的演化过程；
- 明确三件事：年代是推断层、部分高度是分级插补、窗口是核心区而非全市。
- 交互可达性：模块位于长页底部，故模块头部自带「3D 城市」下拉（九城，来自 `buildings-meta.json`），只切换本模块、不触发卷帘/图表重载；顶部「城市」下拉变化时通过 `apply3DControlsState` 同步到模块内下拉。

### 1A.2 数据与生成链
- 轮廓：Overpass API `way[building]`，**© OpenStreetMap contributors（ODbL）**，界面必须出现该署名。
- 年代依据：`data/urban-expansion/{city}_{1990,2000,2014}.geojson`（AUE 建成区轮廓）。
- 窗口选取：`scripts/pick_city_windows.py` 在各城 AUE 2014 最大斑块内滑动 12.7 × 11.1 km 窗口，硬约束「窗口必须覆盖 CBD 锚点」，目标为 `max min(老城面积, 1990 后新增面积)`；结果固化在 `data/buildings/windows.json`。
- 生成：`scripts/gen_city_buildings.py` → `data/buildings/{city}.geojson`（全量逐栋）、`{city}-overview.geojson`（LOD 概览）、`buildings-meta.json`（每城数量/年代分布/高度来源占比/统计量）。

### 1A.3 年代归属（属性 `era`）
`era` = 建筑底面**质心**首次落入建成区范围的时相：1990 / 2000 / 2014；三期范围都不在 → 2024（现状新增）。
- 这是「按建成区位置推断的年代层」，**不是竣工年份**：1990 年已在城市用地范围内的地块，其上的楼可能是后建的；拆旧建新只会归入其现址首次城市化的时相。
- 时间轴默认按 `era ≤ 当前时相` 累计显示；另有「只看新增」= `era == 当前时相`，四个年代新增数之和恒等于总数（`scripts/verify-3d.cjs` 对此有断言）。

### 1A.4 高度取值（属性 `h`，来源记在 `hs`）
优先级：`0` OSM `height` 标签 → `1` `building:levels` × 3.2 m → `2` 同城·同年代·同 `building` 类型中位数（样本 ≥ 8 才用）→ `3` 同城·同年代中位数 → `4` 8 m 兜底。
- 一律按 **1:1 米**渲染，不做垂直夸张（早期体块版的 ×4 夸张已随模块一起删除）。
- 各来源占比在界面读数条与 `buildings-meta.json` 中公开。例：深圳 标签 2.0% / 层数 24.3% / 同类型中位 60.9% / 同年代中位 12.7%。
- 已知效应：中位数插补会让同片建筑高度趋同；北京、武汉窗口内楼高中位仅 3.2 m（老城以低层为主），但 P90 与最高值仍为真实标注（北京 528 m、武汉 476 m）。

### 1A.5 渲染性能与两级 LOD
> **作废数字（2026-11-06 上午及其前的旧实测）**：概览网格 200m、概览体量 14–24%（更早）、逐栋全量 146–219 ms（5–7 fps）、固定阈值 13.6 级、透明度 0.95 与默认瓦片 buffer——这些对应旧产物与旧渲染配置，已被下列两轮实测取代。

实测方法（`scripts/perf-3d.cjs`，可重跑）：headless Chromium + SwiftShader 软件渲染，1600×1000 视口，pitch 56°，5 秒连续方位角扫转，采样 MapLibre `render` 事件间隔取中位数；同时用几何顶点投影统计同屏体块数。软件渲染是**保守下界**，有 GPU 的机器上帧时更低。perf 脚本会先关掉自适应降级再测，让固定两级行语义稳定。

| 配置 | 同屏体块 | 帧时中位（优化前） | 帧时中位（优化后） | fps 前 → 后 |
| --- | --- | --- | --- | --- |
| 出厂 LOD · 默认相机（概览层） | 1,518–2,731 | 45.9–70.3 ms | 31.1–40.2 ms | 14.2–21.8 → 24.9–32.2 |
| 出厂 LOD · 阈值以上 0.4 级（逐栋） | 566–3,235 | 47.2–97.5 ms | 30.9–50.9 ms | 10.3–21.2 → 19.6–32.4 |
| 出厂 LOD · 阈值以上 1.2 级（逐栋） | 164–1,222 | 36.6–75.9 ms | 26.6–43.6 ms | 13.2–27.3 → 22.9–37.6 |
| 对照：默认相机强开逐栋全量 | 5,556–17,302 | 111.8–205.1 ms | 55.7–96.3 ms | 4.9–8.9 → 10.4–18.0 |

- 结论：LOD 阈值把最坏情况的同屏体块数压到约 **1/4–1/13**；两轮合计后，出厂最慢配置从 97.5 ms（10.3 fps）降到 50.9 ms（19.6 fps），强开全量对照约 **2×**（111.8–205.1 → 55.7–96.3 ms）。优化前数字取自同日早些时候的同方法基线复跑（同机；与本页此前记录的 51–75 / 111–206 ms 等属同日采样，抖动内一致）。
- **阈值随相机浮动**，不写死层级：`lodZoom = 默认相机 zoom + 1.4`（上限 16）。因为 +1.4 级意味着同屏面积恒为窗口的约 1/14，无论屏幕多大，逐栋层的同屏体块数都被这个比值约束住；窄屏（390 px）实测阈值 12.9 级，即同一规则的产物。
- 概览层：`OVERVIEW_CELL_DEG = 0.0013`（约 133×145 m，随纬度变化，界面按当前城市换算显示），每格保留最高（同高取底面最大）的一栋；各城 1,393–4,921 栋，为全量的 **22–34%**，九城合计 27,567 栋。
- 图层参数：`bu3d-src` maxzoom 14 + `buffer 24 / tolerance 0.375` + 图层 `minzoom = lodZoom`；`bu3d-ov-src` maxzoom 13 + `buffer 16` + 图层 `maxzoom = lodZoom`；两层共用同一 era 过滤表达式、年代配色与**不透明**渲染（`fill-extrusion-opacity: 1`，透明度 <1 会使 MapLibre 关闭深度写入退化为半透明混合）。`buffer` 从默认 128px 降到 24/16：单栋楼基本不跨瓦片，默认值会把楼在相邻瓦片重复 2–4 份上传；跨缝楼由两侧瓦片的 buffer 条带拼合，放大截图复核无接缝。切换阈值与同屏栋数在地图下方的 LOD 提示条实时说明（`scripts/verify-3d.cjs` 断言阈值 = 相机 + 1.4 且两层区间互补）。
- 相机/画布开销控制：3D 地图 `pixelRatio = min(devicePixelRatio, 1.5)`（高分屏全家桶采样从 2.0 封顶到 1.5，碎片量减约 44%），`antialias` 仅在 dpr≤1.25 保留 MSAA（高分屏靠 1.5x 采样保边缘）；`renderWorldCopies: false`（最小 8.5 级下无世界副本需求）；连续旋转时 LOD 提示条按内容变更检测，不再每帧重写 DOM。
- 底图瓦片限流治理（2026-11-06）：3D 地图切城一次拉起 60–200 个栅格瓦片请求，天地图按 tk 限流时整批 429，MapLibre 对失败瓦片不自动重发，留下成片空洞。措施：天地图栅格请求统一走 `tdtQ://` 自定义协议（`js/basemap.js`，并发上限 6、429/5xx 按 700ms·2ⁿ 退避重试 3 次、队列上限 128、abort 即让槽），切城 easeTo 结束后 `repairBasemapTiles` 对 `loaded()==false` 的栅格源 `reload()` 最多 4 遍补载；链路实测 errored→reload→重新拉起闭环成立。**配额整日耗尽时**（10s 内 ≥8 次 429）自动降级到**多源开源备用链** `Esri Light Gray Canvas → OSM-FR HOT → OSM 官方标准瓦片`（并行探档·**最快返回健康图片者胜出**（3s 封顶，健康=200 且 content-type: image/*——CARTO 免密端点返回「API KEY REQUIRED」占位图 HTTP 200 被校验淘汰出链）；**换装前先把当前视野 3×3 瓦片 fetch 进 HTTP 缓存（3s 封顶）再显示图层**，首图命中缓存即现，省掉逐张慢连空窗；兜底栅格插入锚定在业务图层之下不遮楼，`flushTdtQueue` 立即泄压；横幅公布当前档位署名，隐藏天地图即停发请求让配额冷却；每 60s 探测、命中 2 次自动切回；候选一律要求 WGS84/3857 同基准 + 免密钥 + CORS，GCJ-02 系排除）。`scripts/verify-fallback.cjs` 路由劫持确定性验证（含"链首不可达自动级联"与"层序不遮楼"）。
- **自适应降级保险**：细节层下交互帧时中位数持续 ≥150 ms（<6.7 fps，软件渲染/低端核显的最坏区间）时，LOD 阈值自动上调 +0.7（上限 +1.0）级回到概览层，读数条披露「已临时上调细节阈值」，12s 内不重复触发；换城或点「复位视角」清零重新尝试细节层。`scripts/verify-3d.cjs` 通过 `state.samples` 注入帧样本断言该路径。
- **生长动画**（2026-11-06 晚，年代切换的表现层）：切换年份或播放时，新纳入可见集的年代按"建成区中心向外"的半径次序从地面长到 1:1 高度（easeOutCubic）。工程实现走 `feature-state('gh') + ['coalesce',['feature-state','gh'],['get','h']]`，`setFeatureState` 分波增量写顶点——`fill-extrusion-height` 烘焙在顶点里，逐帧 `setPaintProperty`=重建全瓦片，是禁走的路径。分波节拍播放 55ms/240ms、点选 85ms/420ms，单帧写入上限 700 栋，楼群上限 2,600 栋（超出直接满高）；对比动画：概览层静态 31–40ms/帧 → 动画中位 45.6ms（22fps，p90 53.3ms，同屏 2,731 栋 + 2,600 波次），深圳 2,600 栋波次 19 帧 repaint；反向切换/换城/复位通过 `removeFeatureState` 复位（注意 `setData` 不清 feature-state，需显式清）。
- GeoJSON 切片密度做过对照实验（`scripts/perf-maxzoom.cjs`，maxzoom 14 vs 16，深圳/广州/成都）：帧时差异在噪声范围内且无一致方向，故维持 14，避免瓦片数量与内存翻倍。
- 数据侧预算：单城全量上限 20,000 栋，超出按底面积优先保留（上海抽稀 11,806、成都 7,409、北京 2,226），抽稀数量写入 meta 并在读数条显示。
- 九城合计 103,830 栋全量 + 27,567 栋概览，体积约 26 MB（全量）+ 9 MB（概览）；本地版按城市分片，首次用到才注入脚本。

### 1A.6 已知限制（界面必须说明）
- OSM 建筑收录不完整：轮廓稀疏处不代表实地没有建筑。
- 年代为建成区范围推断层，非竣工年份，不能用于建筑年代统计。
- 约六成高度来自同年代/同类型中位数插补，单栋高度不可作为实测引用。
- 窗口为核心区（约 12.7 × 11.1 km），不是全市域；北京/上海因 AUE 1990 范围过大，框内年代增量天然偏少。
- 现状轮廓没有历史版本，1990 年的三维形态只能用「当时已城市化地块上的现存建筑」近似表达。

## 2. 地图与性能

### 4.1 实例生命周期
- 每页至多一个主地图实例；分析实验室功能A 使用双实例（`mapA`/`mapB`）做卷帘，`pagehide` 时统一 `remove()` 释放，避免 WebGL 上下文泄漏。
- 图层增删统一经 `ensureSource/ensureLayer/removeLayer/removeSource` 守卫，避免重复添加报错。

### 4.1.1 就绪/销毁竞态防护（MapLibre getLayer 抛错）
**症状**：`TypeError: Cannot read properties of undefined (reading 'getLayer')`，演示第二幕之后偶发，整页 JS 中断。

**根因**：`MapLibre.getLayer()` 内部读 `this.style`。以下两种状态会使 `style` 为 `undefined`：

| 情形 | 触发路径 |
| --- | --- |
| ① 样式尚未 load 完成 | 演示模式自动播放时间轴，`setInterval` 中的 `setYear` 在地图就绪前触发 |
| ② **地图已被 `remove()` 销毁** | `bindLifecycle()` 在 `pagehide` 销毁地图，但**时间轴的 `setInterval` 未被清理**；跳转离开改革页后定时器仍在跑，下一 tick 就对已销毁地图调用 `getLayer` |

情形 ② 是本项目的真实根因——堆栈定位为 `setReformYear ← Timeline.onYearChange ← Timeline.setYear`，发生在 `reform.html` 而非分析页（该页已于 2026-10-28 按站点精简要求归档，守卫逻辑仍保留）。

**修复（三重保障）**：
1. `layers.js` 新增 `mapReady(map)` 守卫，在**所有**图层操作入口（`setReformYear` / `setReformVisible` / `setHeritageFilter` / `setHeritageVisible`）统一拦截：同时检测 `_wbRemoved`、`style === undefined`、`isStyleLoaded()`，并用 try/catch 兜底，异常一律视为"不可操作"而非抛出。
2. `reform.js` 在 `pagehide` 时执行 `TIMELINE.pause() + TIMELINE.destroy()`，**根治定时器泄漏**。
3. `analysis.js` 新增 `whenMapReady(map, cb, timeoutMs)` 轮询等待，处理情形 ①。

> **另一处实现陷阱（曾导致回归）**：等待就绪**不能**用 `map.once('load', cb)`。
> `load` 是一次性事件——若它在注册监听之前就已触发，`once` 将**永不回调**，导致
> `loadBuiltup()` 静默提前 `return`、统计框始终为空（`stats=0`）。这种"事件已过"的竞态
> 在快慢机器上表现不一致，极难排查。故`whenMapReady` 采用**轮询 `isStyleLoaded()`**
> （150 ms 间隔、8 s 超时兜底），无论事件是否已触发都能最终执行。

> **方法论要点**：跨页面演示会频繁创建与销毁地图实例。任何持有地图引用的**异步/定时回调**都必须随页面生命周期清理，否则必然在跳转后操作到已销毁对象。

### 4.2 面积精度说明
- `turf.area` 为球面测地面积，与真实椭球（WGS84）存在微小偏差（城市尺度下可忽略）。
- AUE 建成区轮廓为 Landsat 解译近似值，边界存在解译误差；面积量级符合真实城市，但不宜作精确年表。

### 4.3 离线约束
- 所有库与专题数据均本地化（`local/` 提交版把 JSON/GeoJSON 内嵌）；断网时页面、图表、缓冲区与 3D 建筑轮廓可用，仅天地图在线瓦片不可加载，此时底图呈纯色底。
